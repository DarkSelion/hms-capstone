### Maintenance ↔ room status auto-linking
- Reporting maintenance (`MaintenanceController::store`) sets the room to `maintenance` **when it's `available`/`reserved`/`dirty`** (occupied rooms keep `occupied` — guest still in them). The room becomes unbookable on the portal + admin form (both already filter `status = 'available'` / exclude `maintenance`).
- Completing or cancelling (`updateStatus`), deleting a reported request, or moving a request to another room frees the old room via `Room::reconcileStatus()` — but **only when no other open (non-completed/cancelled) requests exist for that room** (`freeRoomIfNoOpenRequests()` helper).
- **Fixed latent bug**: maintenance write routes used `{request}` while controller methods type-hinted `MaintenanceRequest $maintenance`, so implicit route-model binding by name never fired (empty model — updates silently no-op'd, destroy 422'd, assign/status broken). Routes renamed to `{maintenance}`.
- Tests: `backend/tests/Feature/MaintenanceRoomStatusTest.php` (7 — report sets maintenance, occupied untouched, complete→available, complete w/ reservation→reserved, cancel→available, one-of-two open keeps maintenance, delete→available). Backend suite now **290 tests / 938 assertions green**.

### Architecture: User / Guest split
- **`guests` table** — portal/customer accounts. Stores profile + auth (password, remember_token). Authenticatable via Sanctum. HasMany reservations, payments, invoices.
- **`users` table** — staff/admin accounts only. No more `guest_id` FK or guest user rows. Role-based permissions via `roles` table.
- Portal registration creates 1 record in `guests` (no more dual Guest+User creation). Seeded guests get password `password`.
- Admin login no longer filters `role != 'guest'` — `users` table is staff-only.
- Middleware checks `$user instanceof Guest` to assign `'guest'` role; staff users use the existing role map.
- `Reservation`, `Payment`, `Invoice` models keep `guest_id` FK and `guest()` relationship pointing to `guests` table. Portal ReservationController uses `$request->user()` (returns Guest) directly rather than `$user->guest`.
- Frontend PortalUser type flattened — `first_name`, `last_name`, `phone` are top-level fields, no more `guest?` wrapper.

### Same-day late check-out fee (current session)
- **Two-tier departure policy** (industry standard for PH small hotels): departures after the booked `check_out` date keep the extra-night billing (charged at check-out); **same-day late departures** (departing on the booked `check_out` date after the configured check-out time) get a **flat `late_checkout_fee`** added to the total. The two paths are mutually exclusive in `checkOut` — the flat fee is only computed when `actualCheckOut === check_out` (no date change), so it never stacks with the extra-night charge.
- **Settings (Booking tab)**: `late_checkout_fee` (was a dead setting, now wired) + new `check_out_time` (default `12:00`, `booking` group). Both whitelisted in `SettingController::ALLOWED_KEYS` + grouped via `groupForKey`; `check_out_time` added to `SettingsSeeder`.
- **`ReservationController::sameDayLateCheckoutFee()`**: reads `late_checkout_fee`/`check_out_time`/`timezone` settings with fallbacks; applies only when `now($hotelTimezone)` is on the booked `check_out` date and the current hotel-local clock time > `check_out_time` (timezone-aligned to the property setting). Returns 0 when fee ≤ 0, date differs, or before cutoff.
- **`checkOut`**: fee added to the projected total **before** the settlement gate (so "Settle the outstanding balance before checking out." blocks unpaid late fees); fee folding, date recalc, status change, and room→dirty all happen in **ONE DB transaction**, so a failed/retried check-out rolls back cleanly and can never double-charge (absolute-value fold, not `+=`). Writes a `late_checkout` activity log entry with the fee amount.
- **`checkoutPreview`** now returns `late_checkout_fee` + `late_checkout_applies` and includes the fee in `total_amount`/`due_amount` (only when departing on the booked `check_out` date).
- **Frontend**: `CheckoutPreview` TS type gained the two fields; `ReservationCheckInOutModal` fetches the preview for **all** check-outs and shows a "Late check-out fee" standalone amber notice for same-day late departures (mutually exclusive with the departure-changed breakdown); `SettingsPage` Booking tab gained a **Check-out Time (24-hour)** `type="time"` input + helper text; `ActivityLogsPage` action maps include `late_checkout` ("Late Check-Out", warning).
